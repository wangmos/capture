# WeCapture

复刻微信截图体验的 Windows 截图工具。常驻托盘，一个热键唤起：冻结全屏 → 框选（自动吸附窗口/控件）→ 标注 → 复制、保存、钉住、识别文字。

在此之上补了几件微信没有、但用起来很需要的能力：**图上直接拖选文字**、**应用驱动的长截图**，以及一个**可继续编辑的图片查看窗**。

- WPF / .NET 10，单项目，无外部服务
- OCR 使用 PP-OCRv6 small，跑在 ONNX Runtime 上，**完全离线**
- 界面文案为中文

## 功能

### 截图与标注

按热键（默认 `Alt+A`）冻结全部显示器画面，拖动框选；鼠标悬停时会自动吸附到窗口或控件边界。选区确定后可以：

| 工具 | 快捷键 | 说明 |
|---|---|---|
| 矩形 / 椭圆 / 箭头 / 画笔 | `R` `O` `A` `P` | 可选颜色与线宽 |
| 文字 | `T` | 直接在图上输入 |
| 马赛克 | `M` | 拖出矩形即整块打码 |
| 标号 | `N` | 序号自 1 递增；在选区外点击会自动扩展选区把徽章框进来 |
| 撤销 | `Ctrl+Z` | |
| 复制 / 保存 / 钉住 | `Ctrl+C` / `Ctrl+S` / `Ctrl+P` | 双击选区内部也等于复制并退出 |

选区外单击会把最近的边扩展到点击处（保留已有标注），拖动超过 4px 则视为重新框选。多显示器下选区可以跨屏。

**全部快捷键都可以在设置里改绑**，包括工具键。

### 图上选字

框选完成后会自动在后台识别一次文字（可在设置里关闭），随后就能像在网页里一样**直接用鼠标在图上拖选文字**：双击选词、三击选行、`Ctrl+A` 全选、`Ctrl+C` 复制。

压在文字上的手势归文字，其余位置仍然是移动选区、双击复制、外部扩展——所以这个模式默认开着也不会夺走原有操作。

### 长截图

选好区域后点长截图（`Ctrl+L`），**应用自己驱动目标窗口滚动**并逐帧拼接。

不预设滚动步长：由实测位移反推该应用一格滚轮等于多少像素，把每步稳定在视口高度的 45%。定位不可信时回滚一步、步长减半重试，重试仍失败就明确报错——**绝不输出一张静默拼错的图**。跨帧不动的顶部/底部区带会被识别为固定表头表尾并排除，避免重复拼接。

### 图片查看 / 编辑窗

截图后点「识别全部文字」，或长截图完成后，都会进入同一个查看窗：

- 缩放：适应窗口 / 适应宽度 / 1:1 / `Ctrl+滚轮`（以光标为锚点）
- 没选工具时**左键拖动即可平移**（中键随时可平移），不必去拨滚动条定位局部
- 保留与截图时一致的标注工具，可继续编辑，导出时烧进图片
- 文字识别分「识别可见区域」与「全文识别」，结果窗停靠在图片窗旁边并跟随移动

## 安装与运行

需要 **.NET 10 桌面运行时**（发布包不含运行时）。

```powershell
WeCapture.exe              # 常驻托盘
WeCapture.exe --capture    # 立即开始一次截图
WeCapture.exe --settings   # 打开设置
```

已在运行时再次启动不会产生第二个进程：新进程会把请求转交给常驻实例后自行退出。

设置保存在 `%AppData%\WeCapture\settings.json`。

## 从源码构建

```bash
dotnet build WeCapture.csproj
```

产物在 `bin/Debug/net10.0-windows/WeCapture.exe`。

发布（框架依赖，约 46MB）：

```bash
dotnet publish WeCapture.csproj -c Release -o publish --self-contained false
```

其中模型 29.7MB、`onnxruntime.dll` 15.4MB，应用本体仅 0.4MB。

> csproj 固定了 `RuntimeIdentifier=win-x64`。不要去掉：`Microsoft.ML.OnnxRuntime` 会把各平台的原生库（Android `.aar`、Apple `.xcframework.zip`、Linux `.so`）全部拷进输出，多出约 250MB。

## 实现要点

想改代码的话，[CLAUDE.md](CLAUDE.md) 有更详细的架构说明。几个关键约定：

**坐标只有一套真值**——虚拟屏物理像素（`Core/RectI.cs`）。所有模型、标注、导出坐标都在这套坐标系里；DIP 只存在于 WPF 边界上，按各显示器自己的 DPI 换算。

**模型与视图分离**：`Session/SessionModel.cs` 持有整个状态机和全部交互逻辑，不持有任何窗口；每块屏一个覆盖窗，共享同一个模型，所以跨屏选区始终一致。

**标注渲染只写一遍**：`Annotation.Render(DrawingContext, in RenderEnv)` 同时服务于实时覆盖层和最终导出，两者的差别只是裁剪与平移参数。

**OCR 管线**（`Ocr/`）：DB 检测 → 自实现后处理（连通域 + 旋转卡壳最小外接矩形 + 等比外扩，不依赖 OpenCV）→ CTC 识别。字符表从 rec 模型自带的 metadata 读取，杜绝字典与权重对不上。CTC 时间步反推出每个字符的横向区间，这正是"图上选字"的定位依据。

**拼接算法**（`LongShot/ScrollStitcher.cs`）：行签名序列匹配定位位移，匹配分数同时看绝对代价与峰值锐度——一片空白区域里处处都"匹配"，必须判为不可信。
